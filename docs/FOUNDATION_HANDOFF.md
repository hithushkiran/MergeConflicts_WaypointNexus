# Foundation handoff

Run `docker compose up --build`; API startup runs Alembic then `python -m app.seed`. Preserve database volumes during acceptance work; never reset an existing environment. For isolated acceptance, use the separate project in [T09 verification](T09_VERIFICATION.md). Models live in `backend/app/infrastructure/persistence.py`; FastAPI dependencies use `get_db_session` from `infrastructure/database.py`.

Official competition data is read only from Git-ignored `local-data/` and must never be committed. If that official pair is absent in development, Compose seeds clearly synthetic records from `backend/demo-data/`; those IDs use the `DEMO-` prefix and are not competition data. The demo store user is scoped to `DEMO-OUT001`; official seeding scopes it to OUT001. Stable user emails are `store.manager@waypoint.local`, `dispatcher@waypoint.local`, `loader@waypoint.local` (Peliyagoda), and `driver@waypoint.local` (Peliyagoda). Demo date: `2026-03-16`; planning-run lookup: snapshot hash `demo-2026-03-16`. Orders: `DEMO-ORD-FRESH-AMBIENT`, `DEMO-ORD-FRESH-CHILLED`, `DEMO-ORD-STYLE`, `DEMO-ORD-TECH`.

Tables: roles, users, auth_sessions, depots, outlets, vehicles, orders, planning_runs, plan_versions, trips, trip_stops, deferrals, manifest_checks, manifest_versions, shortfalls, delivery_events, proofs_of_delivery, receipts, delivery_issues, audit_events, idempotency_records.
